# Porting 0.9.2

The Python reference moves from `3b0acf7c8b2f` (0.9.1) to **`50d65c1596a9`**
(`50d65c1596a99e5db78c38c0898ca01bfbb105da305e9804f394f08756af7f50`). Unlike 0.9.1, this
round touches one file and one capability: `src/thalovant/models.py`, under the existing
`runtime` capability (no new capability, no new scope declarations needed).

## What changed

**The bug.** `ThalovantReply.claimed` (formerly: any reply whose pipeline stage names
lack `"fallback"` counts as claimed) cannot separate a skill that deliberately answered
from a fallback tier from the fleet's own generic "nothing matched" catch-all skill: OVOS
puts both in the same `FallbackRange(90, 101)` band, so `pipeline_id` alone never tells
them apart. Seen live: `thalovant-skill-home` genuinely turned a light off from the
fallback tier; a satellite listening without a wake word read the reply as unclaimed
and stayed silent.

**The fix.** An opt-in, additive signal. A skill's own `speak` event may carry
`data["meta"] = {"thalovant_claimed": True, ...}` — thalovant-skillkit's `speak_to`/
`emit_speech` already builds `meta = {**(meta or {}), "skill": skill_id}` onto every
`speak` message, so a skill passing `meta={"thalovant_claimed": True}` to that call is
already something every SDK's event collection sees. `claimed` now checks for a `True`
value under that key across `self.events` first, before falling back to the existing
pipeline-tier heuristic. It is checked before `ok` returns early, so it can never rescue
a reply where `ok` is `False` (unhandled, or carrying a `failure_event`). Any other value
under the key — `False`, a string, an int, or the key simply absent — is inert.

```python
THALOVANT_CLAIMED_META_KEY = "thalovant_claimed"

@property
def claimed(self) -> bool:
    if not self.ok:
        return False
    if self._has_asserted_claim():
        return True
    stages = self.pipeline_ids
    if not stages:
        return True
    return any(FALLBACK_PIPELINE_MARK not in stage for stage in stages)

def _has_asserted_claim(self) -> bool:
    return any(
        isinstance(event.data.get("meta"), dict)
        and event.data["meta"].get(THALOVANT_CLAIMED_META_KEY) is True
        for event in self.events
    )
```

**Vectors.** `reply-claim-vectors.json` gains a `metas` array, parallel to the existing
`contexts` array (one entry per event; `null` where that event carries no `meta`, matching
every pre-0.9.2 case unchanged) and 7 new cases: `fallback-claim-asserted` (the
`thalovant-skill-home` shape), `fallback-generic-catch-all-unasserted` (the regression
case: a real fallback-tier `skill_id`, no assertion, still `claimed: false`),
`fallback-claim-false-is-inert`, `fallback-claim-non-bool-is-inert`,
`fallback-claim-on-second-event-still-counts`, `assertion-cannot-rescue-a-failed-reply`,
`assertion-on-an-intent-reply-is-a-no-op`. No existing case's `contexts` or `expected`
changed.

## Acknowledging

For each SDK:

1. Locate this SDK's `ThalovantReply`-equivalent and the `claimed`-equivalent
   check — every SDK already collects `speak`-type events with a `.data`/`meta` (or
   equivalent) accessor for `pipeline_ids`/`skill_ids`; reuse it rather than adding a new
   event-collection path.
2. Add the same constant, spelled in the SDK's own naming convention (e.g.
   `ThalovantClaimedMetaKey` in Go/.NET/Swift PascalCase-adjacent conventions,
   `THALOVANT_CLAIMED_META_KEY`/`thalovantClaimedMetaKey` elsewhere — match how
   `FALLBACK_PIPELINE_MARK`'s equivalent, or the nearest existing public constant, is
   already spelled in that SDK), and export it wherever `claimed`/`pipelineIds`/
   `skillIds` are already exported.
3. Re-vendor `reply-claim-vectors.json` and extend the harness that reads `contexts` to
   also read the parallel `metas` array when present (a harness written before 0.9.2 has
   no `metas` handling and must gain it; this is the one non-mechanical part of the port).
4. Re-run the suite with `THALOVANT_CONFORMANCE_OUT=contracts/conformance-results.json`
   (or the equivalent env var already used for that SDK's `reply-claim` recording, if it
   records this vector at all — most consumers only ever assert against it inline, matching
   how `runtime` has worked since 0.9.0; recording is optional here exactly as it was
   before this round).
5. Append `50d65c1596a9…` to `reference_digests`. No capability re-declaration is needed:
   `runtime` already lists `src/thalovant/models.py` and every consumer already carries it
   as `required`.

Python merges first, as always; each port's own parity check reads Python's `main`, and a
port that vendors the new vectors fails against the old ones committed there.

## Keep it non-breaking

This round adds one module-level constant and changes the internal ordering of one
read-only property's logic; it adds no parameter, no field on a public type, and no new
enum case, so none of 0.9.1's four breaking-by-default shapes apply here. The only per-SDK
judgment call is the constant's exported spelling, and matching the file's own convention
for other similarly-scoped public string constants is enough.
